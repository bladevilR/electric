# 省钱工作台重构设计

## 目标

把现有“功能目录式”电力交易辅助系统重构为每日可执行的省钱闭环。系统只围绕一个结果组织信息：在合规、可靠和风险约束下，降低可验证的综合购电与结算成本。

## 产品原则

1. 省钱金额必须可验证。预计节省和已实现节省分开显示；缺少基准、结算、手续费或偏差成本时显示“未获取”，不显示 0。
2. 数据不可靠时禁止进入执行态。历史快照、跨日数据、点位不足、负荷预测缺失、持仓缺失和限额缺失都必须成为显式阻塞项。
3. 首页只回答三个问题：今天能不能做、可能省多少、下一步做什么。
4. 日常操作固定为四步：接入数据、校验数据、执行省钱策略、结算验收。
5. 高级模型、历史复盘和审计证据放到复核层，不占据日常操作主界面。
6. 系统只生成辅助决策与人工复核材料，不自动提交交易，不绕过 UKey。

## 信息架构

- 顶栏：主体、交易日、数据新鲜度、操作/复核模式。
- 左侧四步导航：接入数据、校验数据、执行省钱策略、结算验收。
- 主工作区：
  - 预计净节省/已实现节省，缺数据时为“未获取”。
  - 当前可执行状态与置信度。
  - 四步进度和唯一主操作。
  - 成本方案对比、行动摘要或阻塞清单。
- 右侧省钱凭证：
  - 公式：基准成本 − 实际结算成本 − 手续费 − 偏差成本。
  - 数据证据、时间戳、缺失项和审计记录。

## 数据判定

- 默认交易日始终是中国时区的今天，不自动回退到最近历史日期。
- 市场价格必须属于所选交易日，且达到 96 点才算完整。
- 可执行建议至少要求：当日价格、96 点负荷预测、持仓、交易限额和人工复核边界。
- 已实现节省至少要求：当日实际负荷、结算结果、基准成本、手续费和偏差成本。
- 快照超过 30 分钟即标记为过期；过期数据不能支撑执行。
- “数据源登记完成”不等于“业务数据到位”，两者必须分开。

## 性能

首页只调用轻量 `/api/workbench` 汇总接口，不启动 Excel 扫描、完整特征构建、回测或结算参考解析。高级计算按需加载。

## 视觉与交互

以已生成的“双层省钱驾驶舱”为骨架，融合“今日省钱作战台”的结果优先和“四步省钱向导”的强校验流程。保留现有蓝绿企业视觉，减少卡片、阴影和导航项目。每个状态只有一个主操作。

## 验收

- 当前无 2026-07-27 数据时，首页明确显示不可执行、预计节省未获取和补采动作。
- 旧快照不能被当成今天的数据。
- 缺失值不显示为 0。
- 首屏只有四个主步骤。
- 首页汇总接口在本地常规数据量下快速返回，不触发重型结算解析。
- Playwright 验证桌面主流程、窄屏布局、主操作、模式切换、控制台错误和视觉层级。

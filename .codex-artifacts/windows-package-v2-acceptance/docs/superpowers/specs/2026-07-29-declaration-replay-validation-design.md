# 历史申报回放验证设计

## 目标

用现有真实历史数据验证“人工申报是否优于系统默认申报”，并把结论作为策略可信度证据接入决策平台。验证不得补造策略动作，不得把预测价差或结算金额直接解释为策略节省。

## 方案选择

采用历史申报回放，而不是虚构策略账本或直接做假设优化器回测。

- 实际申报：`declarationPower`，单位 MW。
- 基线申报：`defaultDeclarationPower`，单位 MW。
- 实际用电：`actualKwh`，单位 kWh。
- 15 分钟申报电量：申报功率 × 0.25，单位 MWh。
- 实际电量：实际用电 ÷ 1000，单位 MWh。

每个同日期、同点位样本分别计算实际申报绝对偏差和默认基线绝对偏差。按全部可比点输出 MAE、相对改善率、胜率、日期覆盖和点位覆盖。

## 判定规则

- 少于 96 个可比点：`insufficient_evidence`。
- 实际申报 MAE 小于默认基线 MAE：`improved`。
- 实际申报 MAE 大于或等于默认基线 MAE：`not_improved`。
- 无论偏差回放结果如何，只要没有可对齐的策略动作、反事实购电成本、手续费和偏差成本，就不能声明策略节省，执行权限保持关闭。

## 系统边界

新增纯函数回放模块，不在浏览器内计算。服务器把回放结果合并到 `/api/strategy-validation`，前端只负责展示。

UI 在“历史策略验证”中新增“申报偏差回放”，明确显示实际申报与默认基线的 MAE、相对改善率和胜率。负改善使用阻断色，并显示“未优于默认申报”。

## 测试

- 单元测试覆盖单位换算、可比样本过滤、改善和退化两条分支。
- 接口继续保持 `executionAllowed: false`，且策略成本节省为 `null`。
- Playwright 验证真实页面显示回放结果、Mock 页面仍有演示标识、控制台无错误、1024px 无横向溢出。

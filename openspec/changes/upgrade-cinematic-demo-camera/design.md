## Context

当前录制器以 1920×1080 页面直接编码，摄影机只在每个步骤末尾执行一次 1.08–1.22 倍变换。该尺度适合教程，但不足以形成评委能够立即感知的产品发布片镜头语言。现有字幕固定在 `body` 叠加层，不随 `#workbenchRoot` 缩放，这一分层可以继续复用。

## Goals / Non-Goals

**Goals:**

- 以 3840×2160 物理像素渲染 1920×1080 CSS 视口，再输出 1080p，保证最高 1.9 倍特写仍清晰。
- 每个关键业务步骤支持 1–3 个摄影机节拍，形成全景、中景、特写、横移和拉回。
- 运镜必须与旁白语义和页面目标绑定，失败时终止录制。
- 字幕删除“AI 解说”标签，正文仍为 36px、最多两行并保留关键词高亮。
- 用密集关键帧和真实播放验收运动幅度、裁切、字幕遮挡与节奏。

**Non-Goals:**

- 不改变前端业务逻辑、交易接口、TTS 文案或节约金额口径。
- 不加入旋转、弹跳、3D 翻页、持续摇晃或无语义装饰动画。
- 不使用低分辨率画面强行放大，也不以静态截图拼接冒充真实页面操作。

## Decisions

1. **使用 2× 设备像素比录制。** Playwright 保持 1920×1080 CSS 视口，通过 CDP 设置 `deviceScaleFactor=2`，录制 3840×2160 原始视频，最终 Lanczos 缩放至 1920×1080。相比扩大 CSS 视口，该方案不会改变页面响应式布局和字幕视觉尺寸。
2. **摄影机改为多节拍时间线。** 每个节拍包含 `at`、`scale`、`focus`、`durationMs`、`motionBlur`，`at` 为镜头时长的 0–1 比例。硬上限 1.9；中景 1.30–1.45，特写 1.60–1.75，英雄金额最高 1.90。
3. **动作分两档。** 点击与局部切换使用 600–850ms；章节引入、跨区域横移使用 1050–1400ms；统一采用 `cubic-bezier(.16,1,.3,1)`，相邻节拍直接从当前变换连接。
4. **叙事镜头固定。** 金额为“全景→三项金额→年度金额→拉回”；曲线为“曲线→AI 建议”；证据为“成本公式→明细”；策略为“现行策略→候选策略→验证路径”。全片 16–20 个可见节拍，至少 6 个节拍缩放不低于 1.6。
5. **字幕仅保留正文。** 删除标签节点和对应样式，容器纵向内边距缩至 18–21px；正文和关键词样式保持独立固定叠加层。

## Risks / Trade-offs

- **4K 浏览器录制不被当前 Playwright 封装器支持** → 先制作短 smoke，必须由 ffprobe 证明原始视频为 3840×2160；不满足则停止，不降级生成成片。
- **高倍率导致目标裁切或字幕覆盖** → 每个节拍使用目标可见矩形计算并限制平移边界；底部目标先滚动到字幕安全区上方。
- **4K 原始视频体积和编码时间增加** → 原始文件仅作为本地中间产物，最终仍为 H.264 1080p；不提交 raw。
- **频繁运镜产生眩晕** → 连续特写最多两个，随后拉回 1.0–1.25；禁止旋转与弹簧过冲。

## Migration Plan

1. 扩展摄影机规格和测试，迁移 `demo-plan.json` 到 beats。
2. 验证 4K smoke 的实际媒体尺寸与字幕清晰度。
3. 重录完整页面视频，复用已经验收的四章 Serena 音频。
4. 合成、密集抽帧和真实播放验收；失败则调整 beats 后重录。
5. 替换参赛 MP4 和验收报告，保留旧提交可随时回滚。

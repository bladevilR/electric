## Context

当前 `trading-ai-system/server.mjs` 固定监听 `127.0.0.1:5177`，本地启动器和测试都依赖这一默认行为。目标 Linux 主机 `10.97.47.88` 已承载其他 Docker 服务，因此本次部署必须使用独立目录、容器/服务名和端口，不能覆盖现有项目。DMZ `172.16.20.233` 是 Windows 服务器，具体公网绑定和现有 Web 代理组件需要在目标机上只读探测后复用。

远端操作通过已授权的 OSMS H5 SSH/SFTP 与 RDP/VNC 完成；共享的 OSMS 浏览器会话还可能被其他发版任务使用，所以每次写操作前必须重新确认主机、用户、工作目录和前台任务状态。

## Goals / Non-Goals

**Goals:**

- 保持本地默认监听行为不变，同时允许生产进程显式监听内网地址。
- 在 `10.97.47.88` 上以独立、可保活、可健康检查的方式运行当前工作区版本。
- 在 `172.16.20.233` 复用已有公网 Web 入口，把请求代理到 Linux 应用。
- 部署前保留现状证据和可恢复配置，失败时能够回滚。
- 通过最终公网 URL 完成真实用户路径验收。

**Non-Goals:**

- 不把系统改成自动交易或自动提交申报。
- 不在本次部署中接入、迁移或伪造 JSPEC/UKey 登录态。
- 不替换两台服务器上已有的其他应用、Docker 栈、IIS/Nginx 站点或证书。
- 不在缺少明确证据时擅自申请新域名、修改公网 DNS 或开放新的边界防火墙策略。

## Decisions

1. **监听地址通过 `HOST` 环境变量配置，默认仍为 `127.0.0.1`。** 这样生产可设置 `HOST=0.0.0.0`，而本地启动器和现有测试不发生破坏性变化。备选方案是直接改为全网监听，但会扩大本地默认暴露面，因此不采用。
2. **Linux 侧使用独立发布目录和固定应用端口，具体端口在远端盘点后选择。** 发布目录按时间保留上一版本，当前版本通过稳定软链或等价服务指向切换；避免覆盖 `review-ai` 等既有目录。备选方案是直接把文件散放到现有项目目录，回滚和边界都不清晰，因此不采用。
3. **优先复用目标机现有 Node 或 Docker 运行时。** 若已有兼容 Node，则用系统服务启动；若只有稳定 Docker，则使用最小镜像/既有基础镜像运行。最终选择必须以远端只读探测为准，不能假设外网可拉取镜像。
4. **DMZ 侧复用现有 IIS/Nginx 组件和证书绑定。** 先导出现有配置或备份相关文件，再新增独立路径/站点规则；不得覆盖默认站点或其他反向代理。若没有可用公网绑定，则把它列为网络/域名阻塞，不以 DMZ 内网地址冒充外网链接。
5. **健康检查分三层。** Linux 本机验证 `/api/health`，DMZ 验证到 Linux 的反代路径，最后从真实公网 URL 验证首页与核心工作台；三层任一失败均不能宣称完成。

## Risks / Trade-offs

- **共享 OSMS 会话与其他发版串线** → 每次操作使用新会话并在命令前打印主机、用户、目录；检测到前台任务时停止输入，改用独立会话。
- **目标端口与现有服务冲突** → 部署前读取监听端口和容器/服务清单，只选未占用端口。
- **DMZ 无现成公网域名/证书或边界映射** → 先读取 IIS/Nginx 绑定和系统网络信息；无法从目标机证实时明确报阻塞，请用户补充网络侧映射，不伪造公网地址。
- **生产数据路径在服务器上缺失** → 健康接口必须可用，业务数据量和关键面板同时验收；缺失的数据保持真实阻塞状态，不用 mock 补绿。
- **当前工作区包含未提交改动和录屏产物** → 使用显式白名单生成部署包，排除日志、录屏、Playwright 会话、`.env` 示例占位配置和其他子项目。

## Migration Plan

1. 本地运行定向测试、配置扫描和部署包清单检查，计算包哈希。
2. 在 Linux 上记录主机身份、监听端口、运行时、磁盘和现有服务；创建独立版本目录并上传包。
3. 启动新服务但暂不接入 DMZ，从 Linux 本机和 DMZ 内网分别验证健康接口。
4. 在 DMZ 备份现有代理配置，新增独立入口并校验配置；切换或重载后验证反代。
5. 从最终公网 URL 验证首页、`/api/health` 和核心工作台，并保存截图/命令证据。
6. 若任一门禁失败，先恢复 DMZ 代理备份，再停止新应用服务并把稳定指向切回上一版本。

## Open Questions

- DMZ 当前对外使用的公网域名、端口、证书绑定和 Web 代理组件是什么？通过目标机只读盘点确认。
- Linux 上可用且不冲突的应用端口、Node/Docker 运行时和持久化目录是什么？通过独立 SSH 会话确认。
- 外网访问是否要求固定路径前缀；若已有域名只能挂载子路径，需要确认前端静态资源和 API 是否支持该前缀，不能只代理首页。

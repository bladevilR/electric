## ADDED Requirements

### Requirement: 可配置的服务监听地址
应用服务 SHALL 接受显式的生产监听地址配置，并在未配置时继续监听 `127.0.0.1`，以保持本地默认安全边界。

#### Scenario: 生产监听内网接口
- **WHEN** 生产进程以 `HOST=0.0.0.0` 和选定端口启动
- **THEN** Linux 主机本机和经授权的 DMZ 主机均可访问 `/api/health`

#### Scenario: 本地默认行为不变
- **WHEN** 启动进程未设置 `HOST`
- **THEN** 服务仅监听 `127.0.0.1`，现有本地启动器仍可通过默认地址访问

### Requirement: 与既有服务隔离的 Linux 部署
部署 SHALL 使用独立版本目录、服务名称和未占用端口，不得覆盖或停止目标机上的既有应用。

#### Scenario: 部署前存在其他应用
- **WHEN** `10.97.47.88` 已运行其他容器或系统服务
- **THEN** 新应用使用不冲突的目录、名称和端口，既有服务在部署后保持运行

### Requirement: 可验证的健康检查与保活
生产部署 MUST 提供进程保活，并使用真实 `/api/health` 响应作为启动和运行验收信号。

#### Scenario: 应用成功启动
- **WHEN** 服务管理器启动新版本
- **THEN** `/api/health` 返回 HTTP 200 且响应中的 `ok` 为 `true`

#### Scenario: 应用启动失败
- **WHEN** 进程退出或健康检查未通过
- **THEN** 部署不得接入 DMZ 公网入口，并必须保留可诊断日志

### Requirement: DMZ 反向代理不破坏既有站点
DMZ 变更 SHALL 先备份相关配置，再通过独立站点、端口或路径规则代理到 Linux 应用，不得覆盖无关站点或证书绑定。

#### Scenario: 复用已有公网入口
- **WHEN** `172.16.20.233` 已有可用的公网域名和 Web 代理组件
- **THEN** 新规则只影响分配给本应用的入口，并把静态资源与 `/api/` 请求一致转发到应用服务器

#### Scenario: 没有可用公网映射
- **WHEN** 目标机盘点无法证明存在公网域名、端口或边界映射
- **THEN** 部署报告明确标记外网入口阻塞，不得把内网地址当作公网完成链接

### Requirement: 可回滚发布
发布 MUST 在切换前记录或备份应用和代理的当前状态，并提供按相反顺序执行的回滚步骤。

#### Scenario: 代理切换后验收失败
- **WHEN** 最终公网验收任一核心检查失败
- **THEN** 系统先恢复 DMZ 代理配置，再停止新应用并恢复上一版本指向

### Requirement: 真实公网端到端验收
完成声明 MUST 基于最终公网 URL 的真实浏览器验收，并包含非敏感证据。

#### Scenario: 公网验收通过
- **WHEN** 从最终公网 URL 打开系统
- **THEN** 首页正常渲染、`/api/health` 返回真实成功响应、核心工作台可用且无占位符或静默降级

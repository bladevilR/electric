## Context

录制发生在王莹的 Windows 真机，系统和 UKey 环境都在该机上；制作与验证主要在 macOS 仓库完成。前端同一时间仍在改版，因此录制自动化不能依赖绝对坐标，也不能与 `workbench.js`、`workbench.css` 形成高冲突修改。比赛要求 MP4、五分钟以内、200MB 以内，旁白确定使用 TTS，接收方的操作要求是“解压后双击挂机”。

## Goals / Non-Goals

**Goals:**

- 单次双击完成环境检查、服务启动、浏览器准备、自动演示、录制和产物检查。
- 每一步按可观察页面状态与网络空闲判断完成，再执行最短展示停留；不把固定 `sleep` 当成功条件。
- 自动演示失败时立即停止后续点击，并留下步骤名、页面截图、日志和实际时间线。
- 录制和 TTS 解耦，允许不重录画面的情况下修改解说、字幕和节奏。
- 不依赖屏幕坐标，不展示 PIN，不点击任何申报/交易提交动作。

**Non-Goals:**

- 不自动输入 UKey PIN、账号、Cookie、证书或其他凭证。
- 不自动执行交易、提交申报或绕过人工复核。
- 本阶段不锁定最终 TTS 供应商或声音；仅生成可对齐的稿件与时间线。
- 本阶段不提前给王莹发送未完成前端版本的录制包。

## Decisions

### 1. 用 FFmpeg `gdigrab` 录全屏，最终包携带 Windows 运行时

脚本从标准输入向 FFmpeg 发送 `q`，确保 MP4 正常收尾；编码固定为 H.264、1080p、30fps、`yuv420p`。选择 FFmpeg 是因为它没有场景、配置文件和插件状态，适合无人值守且能完全通过命令行检查退出码。

备选 OBS 适合人工录制，但无人值守时需要预建 Profile/Scene、处理首次启动和 WebSocket 控制；OpenScreen/Screen Studio 更适合交互式后期，不适合作为无需安装的一键录制依赖。

### 2. 用系统 Edge + Chrome DevTools Protocol 驱动页面

PowerShell 启动独立 Edge 配置目录和远程调试端口；随包 Node 进程直接连接 CDP，不引入 Playwright、npm 依赖或另一套 Chromium。定位器使用语义文本、`data-*` 和稳定 ID，并支持候选定位器，避免前端小改就失效。

### 3. 使用“状态条件 + 网络空闲 + 最短停留”的三层等待

每个分镜定义：

- `ready`：目标元素可见、目标文本出现或目标元素消失；
- `networkIdleMs`：非长连接请求归零后的连续安静窗口；
- `holdMs`：状态达成后留给观众和 TTS 的最短展示时间；
- `timeoutMs`：本步骤硬超时。

状态条件是成功依据，`holdMs` 只控制观看节奏。超时后不继续盲点，自动截图并返回非零退出码。

### 4. 页面内注入演示光标与点击波纹

CDP 点击不会移动系统鼠标。自动演示会注入不读取业务数据的纯视觉层，在点击前平滑移动到目标元素中心、短暂停留并显示波纹；FFmpeg关闭系统鼠标采集，避免出现两个光标。章节标题采用短暂半透明提示，不遮挡指标。

### 5. 录制控制器与分镜执行器采用握手启动

分镜执行器先连接浏览器并创建 `ready` 信号；PowerShell确认后才启动 FFmpeg。FFmpeg稳定写入后创建 `go` 信号，分镜才开始。这样浏览器首次启动和页面预热不会被录进正式素材。

### 6. TTS 使用分段稿件和实际时间线

每个分镜携带 `narration`，执行器记录真实开始、结束和等待耗时。后处理工具依据实际时间线生成配音稿、SSML 和 SRT；最终 TTS 音频以 WAV/MP3 形式交给 FFmpeg 合成。实际步骤比目标时长慢时，字幕和旁白基于实际时间而不是计划时间。

## Risks / Trade-offs

- [Windows 显示缩放或多屏导致录制区域不符] → 环境检查要求主屏至少 1920×1080，录制前启动 Edge kiosk，并把画面统一缩放/补边到 1080p。
- [Edge 策略禁用远程调试] → 启动后检查调试端点；失败则写明阻塞，不静默回退到坐标点击。
- [前端重命名或布局变化] → 分镜支持候选定位器，正式打包前用最终前端跑一次契约测试和真机试录。
- [接口加载慢] → CDP跟踪网络请求，步骤使用状态条件和独立超时；实际耗时写入时间线。
- [FFmpeg 二进制来源或完整性不明] → 最终打包只使用已核验来源与固定 SHA-256 的 `ffmpeg.exe`，清单记录哈希。
- [实际录制超过五分钟或 200MB] → 分镜总目标控制在 3–4 分钟，录后用 `ffprobe` 检查时长、分辨率、编码和大小，超限即返回失败。

## Migration Plan

1. 先在仓库加入独立 `recording/` 工具和测试，不修改并行前端文件。
2. 前端定稿后更新分镜定位器与解说稿。
3. 构建最终便携包时复制录制目录、Node 和固定哈希 FFmpeg/ffprobe。
4. 在 Windows 真机进行 20 秒冒烟试录，再进行完整录制验收。
5. 若录制链路失败，可删除 `recording/` 并继续使用现有启动包；业务系统本身不受影响。

# 10.97.47.88 部署与回滚说明

## 固定边界

- 应用主机：`10.97.47.88`
- 运行账号：`sysadmin`
- 应用端口：`5177`（部署前已确认未占用）
- 发布根目录：`/home/sysadmin/electric/trading-ai-system`
- systemd 服务：`electric-trading-ai.service`
- 执行模式：`human_decision_only`
- 数据模式：离线演示数据；不冒充 JSPEC 实时采集结果

## 目录布局

```text
/home/sysadmin/electric/trading-ai-system/
├── releases/<时间戳>/
├── current -> releases/<当前版本>/
└── shared/
    ├── service.env
    ├── standard-96.json
    └── audit-log.ndjson
```

`service.env` 只放目标环境的非敏感运行参数：

```text
HOST=0.0.0.0
PORT=5177
```

如后续接入模型 Key，必须使用目标机受限权限的环境文件或 secret store，不得写入包、聊天、日志或版本控制。

## 部署顺序

1. 记录当前软链、服务状态、端口和相关文件哈希。
2. 把包解压到新的 `releases/<时间戳>/`，禁止覆盖旧版本。
3. 校验包内 SHA-256 清单，复制离线数据到 `shared/standard-96.json`（只在该文件不存在时初始化）。
4. 原子切换 `current` 软链，安装/更新 systemd 单元并启动服务。
5. 在应用机验证 `http://127.0.0.1:5177/api/health` 和首页。
6. 从 DMZ 验证 `http://10.97.47.88:5177/api/health` 后，才允许接入公网代理。

## 回滚顺序

1. 先恢复 DMZ 代理备份并重载代理。
2. 把 `current` 软链切回记录的上一版本。
3. 执行 `sudo systemctl restart electric-trading-ai.service`。
4. 重新验证本机健康接口；若仍失败，停止服务并保留日志。

`shared` 下的审计日志和数据不随代码版本回滚，避免数据丢失。

## 验收门禁

- `/api/health` 返回 HTTP 200 且 `ok=true`。
- `/api/dataset` 的行数必须为 192，不得为 0。
- 首页、静态资源和核心工作台可加载。
- `review-ai-88-*`、`fund-project-*` 容器状态与部署前一致。
- 最终必须从真实公网链接验收；内网地址不能冒充公网完成链接。

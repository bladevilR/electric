# 回填进度与运行可靠性修复（2026-09-04）

## 原因

原进度仅统计完整的「来源×月份」分片，月内日期已查询也会显示 0%。页面没有定时刷新；空结果漏掉查询间隔，容易触发限流；限流后服务退出循环但仍把任务标记为运行中，没有真正安排重试。

## 已修复

- 以数据库已提交断点计算「来源日」进度，分别列出成功取数、空数据和旧记录待核实数量；不把查询百分比当作数据完整率。采集证据与任务精确关联，不能借用其他任务记录。
- 有数据和无数据查询都按默认 20 秒、±20% 抖动间隔执行。限流退避从 1 分钟递增到最多 30 分钟，使用真实定时器；暂停、切换任务和恢复都不能绕过会话级等待时间。
- 专用浏览器单任务占用；并发启动复用现有任务。暂停允许当前查询原子保存，不开启下一条查询；关闭浏览器先等待查询完成，期间不能恢复或另起采集。
- 服务重启后将中断任务明确标为暂停并保留断点；不冒充仍在运行，不擅自重启旧的登录采集。
- 前端每 3 秒只更新采集状态区域，保留曲线页签、历史筛选、未提交输入及焦点；请求超时/断线显示上次结果与重连状态。
- 平台维护、登录失效、页面变化等明确暂停；一般错误有限重试，避免无检查点的死循环。

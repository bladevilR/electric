# AI 电力交易副驾驶电影感运镜重制设计

日期：2026-08-01

## 目标

把现有“固定全屏页面录制”重制为一支约 3 分 15 秒至 3 分 30 秒的产品演示片：真实页面操作不变，但镜头会根据叙事主动推近、横移、停留和拉远；旁白与画面采用同一节拍，取消莫名空停；把含混的“挑战者”术语正规化并解释清楚，结尾不再重复年度节约金额。

## 已确认问题

- 当前录制器只展示固定全屏，没有摄影机状态。
- `chapter-optimize` 画面比旁白多约 10.9 秒，`chapter-outro` 多约 7.7 秒，形成明显无意义停顿。
- 原片没有解释“挑战者”是待验证的候选策略，也没有建立结算回流与策略验证之间的因果关系，导致页面显得突然且像另一套产品。
- 年度 633.6 万元在前段已形成记忆点，结尾再次重复会显得刻意。

## 技术路线

采用现有 Playwright + Qwen3-TTS + FFmpeg 管线，并吸收 OpenScreen 的 MIT 运镜设计，不引入整套 Electron 编辑器或新的重型视频工程。

参考来源：

- OpenScreen 社区维护版：`https://github.com/getopenscreen/openscreen`
- 连续缩放与横移：`src/components/video-editor/videoPlayback/zoomRegionUtils.ts`
- 弹簧平滑：`src/components/video-editor/videoPlayback/zoomSpring.ts`
- 变换与运动模糊：`src/components/video-editor/videoPlayback/zoomTransform.ts`

若复用或改写其算法，源文件必须保留 MIT 来源说明。

## 运镜架构

### 独立摄影机层

只对 `#workbenchRoot` 应用摄影机变换；录制器生成的章节标题、演示标识、字幕和鼠标效果继续挂在 `body` 的固定叠加层，因此不会随页面一起放大或被裁切。

摄影机状态为：

```js
{
  scale: 1,
  focusX: 0.5,
  focusY: 0.5,
  translateX: 0,
  translateY: 0
}
```

焦点使用 0–1 归一化坐标，既可由目标 DOM 的可见矩形自动计算，也可在分镜中手动修正。

### 分镜相机配置

每个步骤可声明：

```json
{
  "camera": {
    "scale": 1.18,
    "focus": [{ "type": "css", "value": ".savings-projection-grid" }],
    "enterMs": 900,
    "exit": "connect",
    "motionBlur": 0.16
  }
}
```

- 全景交代使用 `scale=1`。
- 普通重点使用 `1.10–1.18`。
- 金额、证据公式和曲线局部最高使用 `1.22`，硬上限 `1.26`。
- 推近时间为 750–1100ms；相邻焦点横移为 900–1200ms。
- 相邻镜头间隔不超过 1500ms 时优先直接横移衔接，不先退回全景。
- 连续两个局部镜头后至少安排一次全景或中景，避免眩晕。
- 变换采用速度连续的弹簧追踪和轻量运动模糊，不使用夸张旋转、3D 翻页或快速抖动。

相机定位器不存在、目标不可见或变换越界时，录制必须明确失败；不得静默降级为固定全屏。

## 音频优先节奏

现有流程先录画面再生成 TTS，导致旁白提前结束。新版改为：

1. 按四个连续叙事段生成 Qwen3-TTS 原始音频。
2. 固定模型、Serena、seed `20260731` 和统一风格指令。
3. 探测每段真实音频时长，再依据句子和源镜头分配画面时间。
4. 每个镜头额外预留 300–800ms 呼吸时间；非标题卡连续静音不得超过 1.2 秒。
5. 根据音频生成最终录制时间表，再启动 Playwright 录制。
6. 禁止通过大幅提速压缩旁白；速度适配仍不得超过 1.15 倍。

四个连续叙事段：

1. 成本价值：问题、AI 闭环、单日/月度/年度演示测算。
2. 数据可信：数据门禁、模型预测和基线验证。
3. 优化决策：96 点曲线、建议、成本证据与人工复核。
4. 结算闭环：已核验成本、结果回流、候选策略验证和价值结尾。

## 新叙事与镜头顺序

1. **开场钩子**：全景卡 → 缓慢推近年度节约潜力；633.6 万元只在这一价值章节出现。
2. **申报工作台**：全景交代 AI 交易副驾驶，随后推近 96 点曲线。
3. **节约金额**：推近单日/月度/年度金额卡，再横移至“演示规模测算”口径。
4. **数据门禁**：横移跟随数据来源、更新时间、完整性状态。
5. **预测证据**：中景展示历史与预测曲线，推近误差和基线验证。
6. **申报优化**：从曲线左侧关键时段横移到右侧 AI 建议，避免整屏长时间静止。
7. **成本证据**：推近统一成本公式，再移到输入来源与操作记录。
8. **人工复核**：拉回中景，展示“未经复核不会自动提交”。
9. **结算结果**：推近 2.4 万元日净成本优化及五项明细，不再重复年化数字。
10. **结果回流**：停留在复盘/审计界面，说明结算结果进入下一交易日的模型评估和风险参数更新。
11. **策略版本验证**：自然切入“策略版本验证中心”，使用“现行策略”和“候选优化策略”两个正式名称。旁白说明：

   > 结算结果不仅用于复盘，也会进入下一轮策略评估。系统以正在使用的现行策略为基准，生成候选优化策略；候选版本必须先完成历史回测和影子运行，在偏差、胜率和风险指标均改善后，才提交人工审批。未经批准，不会替换现行策略，也不会自动申报。

   镜头先推近“现行策略”，再横移至“候选优化策略”，最后落在“历史回测 → 影子运行 → 人工审批”的验证路径上。该段控制在 14–18 秒，只解释持续优化机制，不展开版本管理细节。

12. **结尾卡**：拉远并淡出页面，文案为：

   > AI 负责计算与解释，交易员负责最终决策。  
   > 让每次申报都可执行、可复核、可追溯。

结尾卡不显示 633.6 万元，不再重复策略版本术语，也不引入新的功能名词。

## 视觉节奏

- 预计成片 195–210 秒，绝不超过 5 分钟。
- 运镜不是持续摇动：全片约 10–14 次明确的摄影机动作，其余时间稳定阅读。
- 每次运镜必须服务于旁白中的当前名词，例如说到“成本公式”时才推近公式。
- 字幕宽度和字号保持固定；核心金额、按钮和公式不能被字幕遮挡。
- 开场和结尾保留浅蓝背景，但缩短停留，避免“PPT 片头片尾”感。

## 数据与安全边界

- 继续使用用户授权的本地 `demo=settled` 演示数据。
- 页面持续显示“演示状态、仅用于界面测试、不用于交易”。
- 年度 633.6 万元必须继续标注“按当前演示规模等比例测算，非已实现生产收益”。
- 不点击真实提交按钮，不自动上线策略，不自动发送钉钉。

## 验收标准

1. 真实 MP4 时长 195–210 秒，1920×1080、30fps、H.264/AAC 48kHz。
2. 至少 10 次、至多 14 次可辨认且平滑的推近/横移/拉远；最大缩放不超过 1.26。
3. 字幕、章节标题和演示标识在运镜期间保持固定尺寸与位置。
4. 除开场/结尾设计停顿外，连续无旁白不得超过 1.2 秒。
5. 策略页面标题使用“策略版本验证中心”，对比项使用“现行策略 / 候选优化策略”；界面和旁白不再单独使用 Champion/Challenger 行话。
6. 策略验证段完整说明“结算回流 → 生成候选 → 历史回测 → 影子运行 → 人工审批”，时长为 14–18 秒，且不暗示自动替换或自动申报。
7. 633.6 万元只在价值章节出现一次；结尾不再重复任何年化金额。
8. 四段 TTS 的模型、speaker、seed、instruct 完全一致，任一速度适配不超过 1.15。
9. 关键帧确认无白屏、无越界裁切、无字幕遮挡核心内容、无摄影机跳变。
10. 运镜定位器失败时测试和录制明确报错，不产生无运镜的伪成功成片。
11. 定向回归全部通过；既存外部历史夹具缺失继续如实报告，不使用 mock 补绿。

## 非目标

- 不安装或嵌入完整 OpenScreen 编辑器。
- 不重做前端页面视觉设计。
- 不增加背景音乐、粒子特效、3D 卡片或与业务无关的素材。
- 不把产品演示改成纯动画宣传片；真实可操作页面仍是主要证据。

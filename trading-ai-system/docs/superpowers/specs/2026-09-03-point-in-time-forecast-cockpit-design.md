# 电力交易时点数据、预测复盘与驾驶舱设计

更新时间：2026-09-03  
基线：`main@e14dddceacefa78a251cca825f722f927982bde4`

## 1. 背景与判断

当前系统已经具备 JSPEC 可见业务数据采集、96 点标准化、价格基线预测、申报优化、策略验证和审计展示的骨架，但仍存在四个会直接影响真实使用的问题：

1. 数据字段主要围绕价格、申报和负荷构建，天气、机组、断面、跨区电力和新能源预测尚未形成真实后端数据链。
2. 历史数据按 `日期 + pointIndex` 合并，适合保存最终事实，不足以复原“决策截止时刻当时可见的信息”，存在回测数据泄漏风险。
3. 当前预测结果没有不可变的发布账本，无法严格区分“当时真实发布的预测”“当前模型对历史的重放预测”和“基于结算规则的经济复盘”。
4. 前端虽然已有基础数据、价格预测、申报优化、策略进化和复盘页面，但真实模式下缺少完整来源、数值、更新时间、数据版本、逻辑链和逐点证据；部分天气、机组数据仍为明确的模拟演示值。

本设计将“探索并收集字段信息”作为核心交付，先建立可执行的数据源目录、字段字典和时点数据契约，再建设预测、策略和驾驶舱。模型复杂度排在数据语义、来源可信度和无泄漏复盘之后。

## 2. 目标

### 2.1 核心目标

- 对齐 `ukey现场字段探索任务单.md` 的 P0-1～P0-8 和 P1-1～P1-3，并将现场证据沉淀为机器可读的数据源目录与字段字典。
- 永久区分主动申报、缺省申报、用户日前出清电力、实际负荷/电量、日前临时价、日前最终价、实时当前价和实时最终价，不允许隐式互相代用。
- 接入或预留天气、机组、供给、断面、新能源和跨区电力的合规数据源；无法确认 JSPEC 页面真实字段时标记为 `pending_field_confirmation`。
- 建立 point-in-time 数据底座：所有预测特征均可证明在 `decisionCutoffAt` 前已经可用。
- 建立不可变预测账本和版本化实际结果账本，支持真实发布预测、历史重放和结算经济复盘三套准确度口径。
- 前端以数据源导航页、市场驾驶舱、价格预测、申报策略、历史复盘和模型治理呈现完整数值、来源、逻辑链和结果。
- 保持 `human_decision_only`：不自动申报、不自动交易、不绕过 UKey/CA，不保存任何凭证。

### 2.2 非目标

- 不在当前无 JSPEC 现场页面的电脑上猜测真实表头、接口可得性或业务单位。
- 不把天气再分析数据冒充历史天气预报版本。
- 不把页面 Mock 数值写入真实数据仓或真实准确度统计。
- 不在证据不足时宣称多因素模型已验证、已节省费用或可直接执行。
- 不引入自动下单、自动申报、自动确认、自动模型上线。

## 3. 不可破坏的业务语义

### 3.1 电力和电量

| 业务对象 | 推荐程序字段 | 语义 | 禁止行为 |
|---|---|---|---|
| 用户主动申报 | `userDeclaredPowerMw` | 用户主动提交或历史主动申报的 96 点功率 | 不得用缺省申报、出清电力或实际负荷补齐 |
| 用户缺省申报 | `defaultDeclaredPowerMw` | 平台生成的目标日缺省基线 | 不得覆盖主动申报 |
| 用户日前出清电力 | `dayAheadUserClearedPowerMw` | 用户日前出清页面独立的“出清电力” | 不得映射为主动申报或缺省申报 |
| 实际区间电量 | `actualIntervalEnergyKwh` | 15 分钟区间电量；单位必须现场确认 | 未确认是区间量前不得转换负荷 |
| 实际平均负荷 | `actualAverageLoadMw` | 由已确认的区间电量或页面功率得到 | 只有 `actualIntervalEnergyKwh / 250` 在“15 分钟区间 kWh”确认后才合法 |
| 能量块成交量 | `energyBlockQuantityMwh` | 能量块交易成交电量 | 不得当成 MW 申报功率上下限 |
| 持仓量 | `positionMwh` | 指定执行日/时段的市场持仓 | 不得当成用户负荷或出清电力 |

### 3.2 价格

原始价格必须分列保存，派生“有效价格”不得破坏原始值：

```text
dayAheadUserPriceTemporaryYuanPerMwh
dayAheadUserPriceFinalYuanPerMwh
dayAheadUserPriceEffectiveYuanPerMwh
dayAheadUserPriceEffectiveSource = final | temporary | unavailable

realTimePriceCurrentYuanPerMwh
realTimePriceFinalYuanPerMwh
realTimePriceEffectiveYuanPerMwh
realTimePriceEffectiveSource = final | current | unavailable
```

有效价格选择规则：

1. 最终价是合法数值且其发布状态已确认时，选择最终价。
2. 最终价为空、`-`、`--` 或尚未发布时，可在页面规则现场确认后选择临时/当前价。
3. 原始临时/当前价和最终价都保留，不能把临时值写进最终字段。
4. 训练最终模型标签默认使用最终价；实时监控可另算临时价准确度，但必须标注 `actualLabelVersion=temporary`。
5. 用户日前价、日前公开价、实时公开价、实时加权均价是不同市场口径，任何替代都必须经过显式配置、记录替代原因并在前端告警；默认禁止替代。

## 4. 时间与版本模型

所有时序记录至少包含：

```text
eventTime          业务事件/目标时刻
intervalStart      区间开始
intervalEnd        区间结束
publishedAt        来源正式发布时间
availableAt        系统可合法使用的最早时间
capturedAt         本系统采集时间
sourceRevision     来源修订版本或抓取序号
ingestedAt         入库时间
```

### 4.1 96 点契约

- 统一时区：`Asia/Shanghai`，持久化同时保存 UTC ISO 时间。
- 当前代码约定 `pointIndex=1 -> 00:15`、`pointIndex=96 -> 24:00`，继续沿用为候选标准；每个 P0 页面都必须现场确认首点、末点和区间语义。
- 主键不得只有 `date + pointIndex`。事实表使用：

```text
sourceId + businessDate + pointIndex + sourceRevision
```

- 当前有效视图才按 `sourceId + businessDate + pointIndex` 选择最新合法修订。
- 特征快照使用：

```text
featureSnapshotId + targetTradingDate + pointIndex
```

并保证所有输入记录满足：

```text
availableAt <= decisionCutoffAt
```

### 4.2 天气与小时数据对齐

按字段语义配置对齐方法，并在每个值上保存 `alignmentMethod`：

- 瞬时连续量（温度、露点、湿度、风速）：优先使用原生 15 分钟；仅有小时值时线性插值到区间中点。
- 累积量（降水、辐射能量）：优先使用原生累计周期；若拆分到 15 分钟，必须保存累计起止时刻和拆分方法，不得把小时累计值重复四次。
- 类别量（天气现象、风向类别）：最近时刻或前向保持，并记录方法。
- 所有天气预测必须保存 `forecastIssuedAt` 与 `targetTime`。实际观测或 ERA5/ERA5-Land 只能作为结果、校准或气候背景，不能替代历史预测版本。

## 5. 数据来源分层

### 5.1 来源优先级

1. **授权交易业务数据**：JSPEC 当前账号可见页面或平台允许导出的文件。
2. **官方公开市场披露**：江苏电力交易/调度信息披露和监管要求明确的公开数据。
3. **企业授权内部数据**：苏州轨道实际负荷、运营日历、客流、设备运行和结算核对数据。
4. **授权气象数据**：CMA/国家气象信息中心或企业采购的气象服务，具体接口、许可、延迟和历史深度按合同确认。
5. **开放气象补充源**：ECMWF/NOAA 等公开许可数据，用于开发、基线、交叉核验或自建历史快照。
6. **派生数据**：由上述来源计算，必须记录公式版本、输入快照和计算时间。

### 5.2 来源可信度和可用性状态

每个数据源和字段分别维护：

```text
confirmed_visible          现场确认页面可见
confirmed_export           官方/授权导出确认
code_supported             当前代码已有映射
captured_nonempty           已采到非空真实值
captured_empty              已访问但结果为空
page_visible_code_missing  页面真实存在但代码遗漏
pending_field_confirmation 无真实页面证据，待现场确认
pending_authorization      来源存在但当前授权/许可未确认
mock_only                  仅演示数据
unavailable                已确认不可获得
```

来源级质量维度：完整性、及时性、准确性、修订稳定性、授权状态、历史深度和点位覆盖率。前端不得将 `code_supported` 等同于 `captured_nonempty`。

## 7. 天气数据设计

### 7.1 必备字段

- 地点/区域：`locationId`、经纬度、行政区、江南/江北分区、空间权重版本。
- 版本：`provider`、`modelName`、`forecastIssuedAt`、`targetTime`、`leadMinutes`。
- 气象：温度、体感温度、露点、相对湿度、风速、风向、阵风、降水量、降水概率、云量、地表短波辐射、天气现象代码。
- 质量：原生粒度、对齐方法、来源单位、标准单位、延迟、修订号、缺失原因。

### 7.2 空间口径

建立两套独立聚合权重：

- `suzhou_metro_load_weights_v*`：用于用户负荷，覆盖苏州轨道线路、车辆段和主要站点周边气象点。
- `jiangsu_market_weather_weights_v*`：用于全省价格，按江南/江北、负荷中心或经批准的区域权重聚合。

权重必须版本化；没有真实权重前采用等权基线并明确标注 `experimental`，不得宣称已校准。

### 7.3 来源建议

- 生产优先：CMA/国家气象信息中心或企业已采购服务；接口字段、服务级别、历史预测版本和延迟均标记为待合同确认。
- 开发开放源：ECMWF Open Data 可提供温度、露点、风、降水、云量和短波辐射等字段，但公开入口只保留最近若干次运行，系统必须从上线第一天自存每次运行；完整历史需合法使用档案服务。
- 历史实际天气：CMA 逐小时观测或 ERA5/ERA5-Land 可作为实际结果和气候基线，不得伪装成当时预报。
- 免费历史预报补充：NOAA/NCEI GFS 历史档案可以用于研究交叉验证；进入生产前须核对时区、网格、版本变化、许可和国内访问稳定性。

## 8. 机组、供给与网络设计

### 8.1 目标字段

- 机组/场站：标识、名称脱敏键、区域、类型、额定容量、可用容量。
- 状态：启停状态、计划停运、非计划停运、检修窗口、必开/必停、最小开停时间。
- 出力：日前计划、实时计划、实际出力、上/下爬坡能力、备用容量。
- 新能源：风电/光伏预测、实际出力、预测误差。
- 跨区：受入/外送计划、计划调整、实际交换。
- 网络：重要断面、过江通道 96 点潮流、限额、利用率、阻塞状态。
- 价格拆分：节点电价电能量分量、阻塞分量。

### 8.2 可得性边界

江苏监管要求已经明确增加重要断面与过江通道 96 点潮流/约束/阻塞、区域电源装机和发电量、检修计划、必开必停机组及容量、节点电价能量与阻塞分量、机组/外来电/参数/约束调整等披露内容；但仓库和当前电脑没有真实 JSPEC 页面证据，因此具体菜单、表头、粒度、历史范围和账号可见性全部标记为待现场确认。

如果 JSPEC 当前用户权限看不到某项数据，允许的替代仅包括官方公开披露、平台允许导出或企业正式授权数据。不得探测隐藏接口、绕过权限或根据页面名称猜字段。

## 9. 预测任务拆分

### 9.1 用户负荷预测

目标：`actualAverageLoadMw` 或经确认的实际负荷口径。特征包括：

- 历史同点位负荷和滞后；
- 工作日、周末、节假日、运营日历；
- 苏州气温、体感温度、湿度、制冷/采暖度、连续高温；
- 经授权的客流、加开、线路和设备运行信息。

### 9.2 日前价格预测

目标：明确选择的日前最终价格口径。只使用日前决策截止时点前可用的：

- 系统负荷预测；
- 风电/光伏预测；
- 可用容量、检修、必开必停、备用与爬坡；
- 跨区受入/外送计划；
- 断面限额和预期阻塞；
- 历史价格、日历、天气区域特征。

### 9.3 实时价格/价差预测

优先预测：

```text
realTimeSpread = realTimeEffectivePrice - dayAheadEffectivePrice
```

主要特征：负荷预测误差、新能源预测误差、临时故障、跨区计划调整、爬坡压力、实时断面阻塞和已知日前价格。

### 9.4 模型阶梯

1. 强基线：前一日同点位、前一周同点位、工作日/周末季节性中位数。
2. 可解释候选：LEAR/ElasticNet 或等价稀疏线性模型。
3. 非线性候选：支持分位数损失的 GBDT。
4. 集成：按滚动留出表现加权；无证据时回退强基线。

模型选择必须以滚动时点回测为准，不因模型复杂而晋级。

## 10. 预测账本与准确度

### 10.1 三种评估口径

```text
live_issued    当时真实生成、展示给交易员且不可变的预测
point_in_time_replay  当前候选模型按历史决策截止时点重放
settlement_replay    预测进入申报策略后按真实结算规则复盘
```

三个口径独立展示，禁止合并成一个“历史准确率”。

### 10.2 不可变预测记录

每次预测生成一个 `forecastRunId`，保存：

- 生成时间、决策截止时间、目标交易日、pointIndex；
- 模型/特征/代码版本、训练窗口、split 标识；
- point/P10/P50/P90/尖峰概率；
- featureSnapshotId、输入完整性、降级原因；
- `live_issued` 或 `point_in_time_replay` 类型。

实际结果以新版本追加，不修改原预测：临时价、最终价、来源修订、回填时间和结算版本分别保存。

### 10.3 指标

- 点预测：MAE、RMSE、Bias、MASE、相对强基线 skill。
- 概率预测：P10/P50/P90 pinball loss、80% 区间覆盖率、平均区间宽度、WIS/CRPS（数据允许时）。
- 事件：尖峰/阈值事件 Precision、Recall、PR-AUC、Brier Score、方向准确率。
- 分层：点位、峰平谷、工作日/周末、季节、高温、停机、阻塞、新能源偏差。
- 经济：相对缺省申报、实际人工申报和完美预知下界的成本、regret、日/月胜率。

MAPE 不作为主指标，避免低价或接近零价格导致失真。

### 10.4 晋级门禁

门槛全部配置化。首版建议：

- 仅展示基线：至少 5 个历史有效日，仍标记 `baseline_only`。
- 进入候选比较：至少 30 个完整日和 2,880 个可比点。
- 进入影子运行：至少 60 个滚动留出日，且数据泄漏审计通过。
- 可申请 Champion：至少 90 个连续样本外日；相对强基线 MAE 改善达到配置门槛，日胜率、尖峰召回、区间覆盖和经济指标均不过度退化。
- 晋级必须人工审批，任何门槛不满足时继续基线或影子运行。

## 11. 策略逻辑链

每个目标点和每个重点窗口都生成结构化 `strategyTrace`：

```text
1. 数据证据
   来源、发布时间、目标时刻、覆盖率、缺失和替代
2. 负荷判断
   缺省申报、负荷 P10/P50/P90、天气修正
3. 价格判断
   日前/实时 P10/P50/P90、价差方向、尖峰概率
4. 供给和网络判断
   可用容量、停机、备用、爬坡、跨区、断面阻塞
5. 持仓和限额
   出清电力、能量块、持仓、可买可卖量、MW 申报边界
6. 目标函数与约束
   期望成本、偏差成本、风险项、CVaR、平滑和边界
7. 推荐结果
   基线、候选、最终人工复核值、变化量、置信度、降级原因
```

每个结论必须引用具体 `evidenceRef`、`featureSnapshotId`、`forecastRunId` 和模型版本。缺少关键数据时显示阻断或降级，不用 Mock 填空。

## 12. 前端信息架构

### 12.1 一级导航

1. **数据源与质量**：来源目录、字段字典、授权状态、更新时间、96 点覆盖、修订和证据。
2. **市场驾驶舱**：目标日全局态势、供需、天气、机组、断面、价格、事件和风险。
3. **价格预测**：96 点 P10/P50/P90、实际值、基线/候选、置信度和特征贡献。
4. **申报策略**：主动/缺省/出清/实际/推荐五条曲线，逻辑链、约束和人工复核。
5. **历史复盘**：真实发布、时点重放、最终结算三类准确度与场景分解。
6. **模型治理**：Champion/Challenger、版本、数据窗、门槛、审批、回滚和审计。

### 12.2 数据源与质量页

- P0/P1/天气/机组/预测账本分组导航。
- 每项显示真实数值行数、覆盖日期、非空点数、原生粒度、单位、最近发布时间、采集时间、延迟和状态。
- 提供宽表：数据域、来源、页面原始表头、程序字段、业务含义、单位、类型、粒度、关联键、必填、空值规则、延迟、历史深度、确认状态、证据、待办。
- 任一字段可展开显示脱敏样例、原始值、标准值、转换规则和证据文件。

### 12.3 市场驾驶舱

顶部固定：目标交易日、`as of` 截止时点、市场阶段、数据完整度和模式（真实/演示）。

关键卡片只显示有来源的数值：

- 用户负荷 P50/P90；
- 系统负荷/净负荷；
- 可用容量、停机容量、备用率、爬坡压力；
- 风电/光伏预测；
- 跨区受入；
- 重要断面利用率和阻塞；
- 日前临时/最终价、实时当前/最终价；
- 数据缺失和高风险事件数。

主图区：

- 96 点价格分布与实际价格；
- 用户负荷、缺省申报、主动申报、出清电力；
- 系统净负荷和可用容量；
- 温度/辐射/风速；
- 检修、故障、跨区调整和阻塞事件带。

点击任何数值或曲线点打开“证据抽屉”，显示来源、原始表头/字段、原始值、标准值、单位转换、发布时间、目标时间、采集时间、版本和质量标记。

### 12.4 价格预测页

- 明确目标价格口径和临时/最终状态。
- 同图比较强基线、Champion、Challenger 和实际值。
- 表格逐点显示 P10/P50/P90、区间宽度、尖峰概率、数据完整度、模型版本。
- 特征解释只显示可复核贡献；树模型可用稳定的聚合贡献，不能把相关性写成因果。
- 数据不足时显示 `baseline_only`、`insufficient_history` 或 `blocked_by_missing_source`。

### 12.5 申报策略页

必须同时、明确标注：

- 主动申报；
- 缺省申报；
- 用户日前出清电力；
- 实际平均负荷/电量；
- 推荐申报。

默认不把不同单位画在同一纵轴。MW、MWh、kWh、元/MWh 和元分别使用独立轴或独立图层。页面展示逐点逻辑链、重点窗口解释、硬约束、降级/阻断原因和人工复核状态。

### 12.6 历史复盘页

- 顶部切换：真实发布 / 时点重放 / 结算经济复盘。
- 展示样本覆盖、数据版本和最终价回填进度。
- 展示总体及点位/场景指标、可靠性曲线、区间覆盖、尖峰召回和模型差异显著性。
- 单次预测可回放当时驾驶舱、输入快照、模型版本、策略逻辑和最终结果。

## 14. 真实与演示模式

- `real`：只显示真实/授权来源；缺失即缺失，不回退到 Mock。
- `demo`：所有模拟字段、指标、曲线和金额持续显示“演示环境 · 模拟输入”。
- `replay`：显示指定历史 `asOf` 的快照，禁止加载最终修订替代当时版本。
- API 和 UI 的模式标识同时存在，避免仅靠文案区分。

## 15. 安全与合规

- 只读取页面可见业务数据、平台允许导出和公开/授权数据源。
- 拒绝 Cookie、Token、Authorization、UKey PIN、证书、私钥、密码和浏览器存储内容。
- 证据文件默认保存在本地受控目录；公开仓库只保存脱敏字段结构和状态，不提交真实敏感业务明细。
- 不调用未公开接口，不绕过权限，不自动申报或交易。
- 所有策略输出均标记 `executionAllowed=false`，必须人工复核。

## 16. 迁移与实施顺序

1. 先落地数据源目录、字段字典、语义校验和 point-in-time 存储；修复用户日前出清 `出清电力` 及临时/最终价映射。
2. 再落地特征快照、预测账本、实际结果账本和准确度 API；当前基线预测先接入账本。
3. 再接天气、机组、断面和新能源来源；来源未确认时只显示缺口，不进入真实模型。
4. 再引入可解释多因素模型和分位数模型，执行滚动时点回测和影子运行。
5. 最后重构前端导航与驾驶舱，消费真实 API，并补全证据抽屉、逻辑链和复盘回放。

前端 Mock 页面可作为视觉参考，但不能先于真实 API 契约固化业务含义。

## 17. 验收标准

- 字段字典覆盖 P0-1～P0-8、P1-1～P1-3、天气、机组/供给、预测账本和准确度，且每行含用户要求的完整列。
- P0-3 的 `出清电力` 有独立字段；临时价、最终价和有效价三者可同时复核。
- 主动申报、缺省申报、出清电力和实际负荷之间不存在隐式回填。
- 任意预测都能导出其 `decisionCutoffAt`、feature snapshot、模型/代码版本和 96 点结果。
- 任意准确度指标都能追溯到预测发布记录和实际值版本。
- 历史重放查询不会读取 `availableAt > decisionCutoffAt` 的记录。
- 真实模式中天气/机组字段不可得时显示 `pending` 或缺失，不显示模拟数值。
- 驾驶舱所有关键数值和曲线点可打开证据抽屉。
- 申报策略页同时显示并正确命名主动申报、缺省申报、用户日前出清电力、实际负荷和推荐值。
- 全量测试通过；浏览器在 1440、1024、768、390、320 px 无页面级横向溢出，宽表和图表只在局部容器滚动。
- 系统继续拒绝敏感字段，且不存在自动申报、自动交易和自动模型晋级路径。

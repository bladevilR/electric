# Playwright 全量历史采集与预测证据闭环设计

日期：2026-09-03

状态：已确认设计，待实施计划
目标视觉稿：`docs/design-reference/data-forecast-evidence-playwright-target-v1.png`

## 1. 目标

在现有电力交易 AI 系统内增加一套可长期运行的本地采集与证据闭环：

1. 系统自带 Playwright 运行时，启动独立、可见、可持久化的 Chrome 采集窗口。
2. 用户首次通过 UKey 手工登录，此后复用该专用浏览器会话。
3. 自动回填平台允许查询的全部历史数据，并支持断点续跑、限速退避和幂等去重。
4. 形成价格、温度、负荷的“预测—实际”历史对照。
5. 将正式价格预测、输入快照、实际结果和准确率保存为可审计证据。
6. 在“数据与预测依据”页面统一呈现采集状态、预测曲线、历史查询、策略形成依据和可视化微调演示。

本设计不包含自动输入 UKey PIN、读取登录凭据、执行交易或绕过平台安全控制。

## 2. 已确认的关键决策

- 采集方式：Playwright 驱动专用的可见 Chrome，而非连接用户日常 Chrome。
- 登录方式：首次由用户手工完成 UKey 登录；登录失效时暂停并提示恢复。
- 历史范围：回填平台能够查询的全部历史，不设置固定天数上限。
- 正式存储：单机 SQLite 为唯一正式数据源；JSON/CSV 仅作为迁移输入和导出格式。
- 正式预测：只有真实发布时写入的 `live_issued` 预测才参与历史准确率评价。
- 前端入口：保留一个统一导航项目“数据与预测依据”，内部使用价格、温度、负荷三个预测页签。

## 3. 总体架构

```text
任务调度器
  -> Playwright 浏览器运行时
  -> 数据源页面适配器
  -> 页面结果校验与标准化
  -> SQLite 证据库
  -> 特征快照与预测发布
  -> 实际结果回填与准确率计算
  -> 数据与预测依据工作台
```

每一层通过明确的数据结构通信，浏览器控制、页面解析、数据存储、预测计算和页面展示互不直接依赖内部实现。

## 4. 浏览器运行时

### 4.1 启动方式

- 使用项目已安装的 `playwright` 包。
- 正式采集优先启动本机稳定版 Google Chrome，以兼容 UKey、中间件和系统证书。
- Playwright 自带 Chromium 只用于自动测试和演示环境，不作为正式 UKey 采集器。
- 使用 `launchPersistentContext` 启动独立用户目录 `.browser/jspec-playwright-profile`。
- 只保留一个受控业务页签；用户可以看到页面操作，但不会影响日常 Chrome。

### 4.2 状态机

```text
uninitialized
  -> login_required
  -> ready
  -> collecting
  -> paused | rate_limited | login_expired | page_changed | error
  -> ready
```

状态判断来自页面 URL、业务首页可见元素和查询结果特征，不读取或导出 Cookie、密码、PIN、证书及令牌。

### 4.3 生命周期

- 系统启动时不强制弹出浏览器，用户点击“启动专用 Chrome”后创建上下文。
- 登录成功后记录非敏感会话状态和最后健康检查时间。
- 浏览器意外关闭时，当前任务安全暂停并保留检查点。
- 登录失效时不自动尝试登录，前端明确显示“需要重新登录”。
- 同一时刻只允许一个采集任务控制浏览器。

## 5. 数据源适配器

每个数据源实现统一接口：

```text
detect(page)                     判断当前页面和登录状态
navigate(page)                   进入目标业务模块
discoverBounds(page)             探测最早和最晚可查询日期
setQuery(page, query)            设置日期、区域及其他条件
submit(page)                     触发查询
waitForResult(page)              等待加载完成或业务错误
extract(page)                    提取表格、曲线或卡片数据
validate(result, query)          校验日期、字段、点数和单位
nextPage(page)                   处理分页
fingerprint(page)                生成页面结构指纹
```

首批适配器：

- 日前价格、实时价格、结算价格。
- 天气实况、温度预测。
- 实际负荷、负荷预测。

后续供需、机组和网络约束数据沿用同一接口扩展。

适配器必须真实操作日期控件、查询按钮和分页。固定路由跳转只能用于导航，不能作为完成历史采集的依据。

## 6. 全量历史回填

### 6.1 任务拆分

1. 适配器先探测平台最早与最晚可查询日期。
2. 调度器创建“数据源 × 月份”的分片任务。
3. 分片内部按交易日执行，逐日保存检查点。
4. 每个交易日按页提取并写入数据库；写入成功后才更新进度。
5. 完成全部历史后，进入每日增量采集模式。

### 6.2 限速与恢复

- 查询之间使用带抖动的安全间隔，默认沿用当前 20 秒保守节奏。
- 识别高频访问提示后立即暂停该数据源，并指数退避。
- 网络错误、页面超时和浏览器关闭可自动重试；登录失效和页面结构变化必须人工介入。
- 失败任务保留查询条件、错误分类、页面截图路径和结构指纹。
- 重启服务后从最后成功检查点继续，不重复制造数据版本。

### 6.3 成功条件

一次采集只有同时满足以下条件才算成功：

- 页面确认为目标业务模块。
- 页面显示的查询日期与任务日期一致。
- 必需列、单位和区域匹配。
- 96 点数据按业务要求完整，或明确记录可接受的缺口原因。
- 原始证据摘要与标准化事实已在同一事务中写入。

空表、重定向、登录页和列结构变化均不得被标记为成功。

## 7. SQLite 数据模型

数据库建议保存为 `data/trading-evidence.sqlite`。

### 7.1 采集表

- `collection_jobs`：任务范围、状态、总分片数、成功数、失败数、时间戳。
- `collection_chunks`：数据源、月份、当前日期、重试次数、检查点和错误分类。
- `raw_captures`：页面 URL、查询条件、采集时间、结构指纹、行数、证据截图路径和内容摘要哈希。
- `facts`：来源、字段、业务日期、点位、数值、单位、可用时间、采集时间和来源修订号。

`facts` 使用“来源 + 字段 + 业务日期 + 点位/实体 + 来源修订号”唯一约束，确保幂等和版本可追溯。

### 7.2 预测表

- `feature_snapshots`：预测截止时间可用的输入事实集合、完整度和版本。
- `forecast_runs`：运行类型、目标日期、生成时间、截止时间、模型与代码版本。
- `forecast_points`：96 点预测值、P10/P50/P90 和输入完整度。
- `outcomes`：实际值、临时/最终/结算修订版本及发布时间。
- `accuracy_metrics`：按预测运行、模型、日期、时段聚合的评估指标。

### 7.3 迁移与导出

- 首次启动时将现有 visible history、point-in-time store、forecast ledger 和 outcome ledger JSON 导入 SQLite。
- 迁移过程幂等，原文件保留为备份，不直接删除。
- 页面查询只读取 SQLite；JSON/CSV 由导出接口即时生成。
- 数据库不得保存任何凭据属性，写入层继续执行敏感字段名拒绝校验。

## 8. 预测与实际结果闭环

### 8.1 特征快照

每次价格预测冻结当时可用的数据：

- 历史价格和近期价格特征。
- 当时版本的温度预测与负荷预测。
- 日历、节假日及已接入的供需特征。
- 各输入来源、截止时间、缺失率和修订版本。

快照创建后不可修改。事后更新的数据形成新事实版本，不反写旧快照。

### 8.2 发布门槛

- 少于 5 个完整交易日：不输出预测。
- 5 至 29 个完整交易日：仅输出低置信度基线，不标记为正式模型。
- 至少 30 个完整交易日且滚动回测通过：允许发布正式 `live_issued` 预测。

正式运行保存 96 点 P10/P50/P90、模型版本、代码提交、训练范围、特征快照和决策截止时间。

### 8.3 结果匹配

- 实际价格进入 `outcomes`，不同结算修订并存。
- 评价只匹配同一目标字段、交易日期和点位。
- 默认展示最终实际结果，同时允许切换临时、结算初版和结算终版。
- 历史评价不使用事后重算预测冒充正式预测。

核心指标：MAE、RMSE、Bias、MAPE、MASE、峰值精确率/召回率、Brier 分数、P10/P50/P90 pinball loss、80% 区间覆盖率和区间宽度。

## 9. 策略依据

页面以以下链路解释申报策略：

```text
历史价格 + 温度预测 + 负荷预测 + 日历/供需特征
  -> 价格分布预测
  -> 成本与偏差风险目标
  -> 约束优化
  -> 96 点申报策略
```

价格模型的解释性表达为：

```text
P(t) = f(历史价格, 温度预测, 负荷预测, 日历特征, 供需特征)
```

策略优化同时展示成本项、偏差惩罚、风险项和业务约束。每个节点可查看数据来源、算法版本、公式、截止时间、完整度和对结果的贡献。

策略微调仅生成临时模拟结果，不修改正式预测、正式申报或历史证据。

## 10. 前端信息架构

唯一导航入口为“数据与预测依据”。

### 10.1 顶部状态条

- 专用 Chrome 状态。
- UKey 登录状态。
- 历史覆盖起止日期。
- 全量回填进度和最后更新时间。
- 启动浏览器、开始/暂停/恢复回填等明确操作。

### 10.2 三个预测页签

价格预测、温度预测和负荷预测采用统一布局：

- 预测与实际双曲线。
- 不确定性区间。
- 日期范围、区域、模型和实际结果版本筛选。
- 关键准确率指标。
- 96 点明细。
- 右侧“预测依据”面板。

### 10.3 预测依据面板

常驻右侧，展示数据来源、核心公式、算法版本、决策截止时间、数据完整度、置信度和可追溯证据入口。详细内容使用内部折叠项，避免页面继续纵向堆叠。

### 10.4 策略形成与微调

- 使用连接节点展示三类输入、价格分布、风险优化和 96 点策略。
- 显示主要贡献比例和当前高亮路径。
- 微调区域提供价格、温度、负荷权重和风险偏好控制。
- 基准策略与模拟策略曲线同图对比，并固定显示“仅演示，不修改正式策略”。

### 10.5 基础数据历史

支持按日期、来源、字段、完整度和版本查询，并可在曲线、明细和采集证据之间切换。桌面端使用主图表加右侧依据面板，移动端改为卡片和抽屉。

## 11. 服务接口

建议新增或重构以下本地接口：

- `POST /api/collector/browser/start`
- `POST /api/collector/browser/stop`
- `GET /api/collector/status`
- `POST /api/collector/jobs/backfill`
- `POST /api/collector/jobs/:id/pause`
- `POST /api/collector/jobs/:id/resume`
- `GET /api/collector/jobs/:id`
- `GET /api/history/facts`
- `GET /api/history/coverage`
- `POST /api/forecast/publish`
- `GET /api/forecast/runs`
- `GET /api/forecast/accuracy`

所有写接口记录本地操作者、时间、请求范围和结果摘要。采集器内部错误转换为稳定错误码，前端不依赖 Playwright 的原始异常字符串。

## 12. 错误与证据策略

错误分为：登录失效、限流、查询无数据、页面结构变化、字段校验失败、浏览器关闭、网络超时、存储失败和预测门槛不足。

- 登录失效：暂停所有任务并提示重新登录。
- 限流：暂停当前数据源，显示预计恢复时间。
- 查询无数据：区分合法空值和页面异常，不自动补零。
- 页面结构变化：保存截图、结构指纹和目标选择器诊断。
- 存储失败：事务回滚，不推进检查点。
- 预测门槛不足：展示缺失原因，不返回伪预测。

成功和失败均进入审计日志，敏感字段在日志写入前被拒绝或脱敏。

## 13. 测试策略

### 13.1 单元测试

- 任务切片、断点恢复、幂等键和限速退避。
- 页面适配器的日期控件、分页和字段映射。
- SQLite 事务、唯一约束、版本查询和 JSON 迁移。
- 特征快照冻结、预测发布门槛、结果版本选择和准确率计算。

### 13.2 Playwright 组件与端到端测试

- 使用本地模拟业务页覆盖登录、日期查询、分页、空数据、限流和页面改版场景。
- 验证专用浏览器状态机和任务恢复。
- 验证三类预测页签、历史筛选、依据面板、策略节点和微调演示。
- 检查 320 至 1440 像素宽度无横向溢出、关键操作可键盘完成、无控制台错误。

### 13.3 现场验收

1. 用户通过 UKey 登录专用 Chrome。
2. 从一个小日期区间试采，确认字段与 96 点完整度。
3. 启动全部历史回填并验证重启续跑。
4. 查询任意历史日期的价格、温度和负荷数据。
5. 生成一条正式预测并确认账本不可覆盖。
6. 实际结果到达后展示预测—实际曲线和准确率。
7. 验证页面能从策略节点追溯到输入事实和采集证据。

## 14. 交付分期

实施按依赖顺序拆分：

1. SQLite 存储层和旧数据迁移。
2. Playwright 持久化浏览器运行时和状态机。
3. 三类首批页面适配器与全量回填调度器。
4. 特征快照、正式预测发布和实际结果闭环。
5. “数据与预测依据”目标页面实现。
6. 真实 UKey 小范围试采、全量任务启动和现场验收。

各阶段均可独立验证，不以界面演示成功替代真实数据闭环成功。

# 电力交易策略助手

这是一个本地运行的电力交易辅助工具。它把数据进度、结算参考、价格预测、预测验证、省钱策略和交易草稿复核放在一个工作台里，帮助你更快看清“现在能判断什么、还缺什么数据”。

## 一分钟上手

打开：

```text
一分钟上手.html
```

或者直接双击：

```text
启动系统.bat
```

启动后访问：

```text
http://127.0.0.1:5177/
```

## 日常使用

1. 插上 UKey。
2. 双击 `启动系统.bat`。
3. 在当前工作台左侧点击“价格预测”，查看“累计 N/5 个历史交易日”。
4. 每个交易日用 Chrome 登录 JSPEC 并成功采集有效价格数据；仅打开程序不会累计。
5. 累计 5 个有效历史交易日后，第 6 个交易日有目标日数据时会自动启用历史同点位中位数基线预测。
6. 回到“申报优化”复核申报建议；该页面的历史基线使用 42 日同点位模型，和价格预测的 5 个有效历史交易日门槛是两套不同口径。
7. 需要时再进入“策略进化”查看策略版本验证，或进入“复盘回顾”查看结算后的审计证据。
8. 样例和演示测算不等于实际结算收益；所有建议均须人工复核，系统不会自动提交申报或交易。

## Linux 外网演示部署

面向 `10.97.47.88` 和 DMZ `172.16.20.233` 的定向部署使用 `deploy/linux/` 下的白名单、systemd 单元及中文部署/回滚说明。生产进程显式设置 `HOST=0.0.0.0`；未设置时服务仍只监听 `127.0.0.1`。

该部署默认使用离线演示数据并保持 `human_decision_only`，不代表 JSPEC 实时采集已接通，也不会自动提交交易。

样例和演示测算仅用于说明流程，不等于实际结算收益；所有建议均须人工复核。

## 环境要求

普通查看和离线演示：

- Windows 10/11。
- PowerShell 可以运行。
- 浏览器可以访问 `http://127.0.0.1:5177/`。
- 5177 端口没有被其他程序占用。
- 先解压整个文件夹，再双击 `启动系统.bat`。
- 开箱包自带 Node 运行时和样本数据，不需要用户单独安装 Node.js。

实时采集和全量慢采：

- 插着 UKey。
- 已安装 CA/UKey 驱动。
- 有 JSPEC 账号并能访问交易平台。
- 有 Chrome 或 Edge。
- 慢采期间保持 UKey、数据窗口和本地服务打开。

如果浏览器提示 `127.0.0.1` 无法访问，通常是本地服务还没有启动成功。启动失败时黑色窗口会保持打开，不要关闭；请把窗口内容以及系统文件夹内 `logs` 目录发给技术支持。`logs/startup.log` 记录启动过程，`logs/server.stderr.log` 记录服务报错。

## 它能做什么

- 整理已有 raw captures 和本地 Excel 结算参考。
- 把价格、申报、负荷、结算等数据转成 96 点特征。
- 做价格预测基线和 walk-forward 验证。
- 给出省钱策略建议、置信度和数据缺口。
- 用一键全量慢采补齐 JSPEC 页面上可见的业务表格。
- 生成报告和交易草稿复核材料。
- **策略自进化决策中枢**（工作台「策略进化」）：
  - 策略进化中心：Champion / Challenger 版本树与参数差异
  - 智能实验中心：漂移诊断、参数搜索、滚动回测、影子运行
  - 运营统计中心：改善、胜率、MAE、漂移预警、回撤
  - 安全治理中心：人工审批上线、审计轨迹、一键回滚（禁止自动上线/自动申报）

## 它不会做什么

- 不会读取 Cookie、Token、证书私钥或 UKey PIN。
- 不会绕过 CA/UKey 确认。
- 不会自动提交申报或交易。
- 不会在策略进化中自动把挑战者推上线；必须人工审批。
- 在缺少目标日实际负荷、结算、持仓和交易限额时，不会输出可直接执行的电量。
- 不会把样例或演示测算当作实际结算收益。

# 时点数据与规范字段

生产采集只处理当前账号授权的只读页面可见数据。数据源和字段契约分别位于
`config/data-sources.json` 与 `config/field-catalog.json`；用户日前出清电力使用
`dayAheadUserClearedPowerMw`，不得回填主动申报、缺省申报或实际负荷。

日前价格按临时价、最终价、有效价三类保存，有效价仅是查询视图。模型输入必须满足
`availableAt <= decisionCutoffAt`，无日期的时变数据不会复制到历史日期。

只读接口：`/api/data-sources`、`/api/field-catalog` 和 `/api/point-in-time/context`。

准确度分为真实发布预测、历史时点重放、最终结算复盘三种视图，三者不得混合。用新模型重新运行
旧数据不等于当时真实发布的预测。用户账本保存在 LocalAppData 的 `forecast-ledger.json`、
`outcome-ledger.json` 和 `point-in-time-facts.json`，不得放入公开交付包。
# 六视图决策工作流

先核数据源与质量，再看市场驾驶舱，再看价格预测，再核申报策略逻辑链，事后进入历史复盘，模型变更进入模型治理。天气、机组、供给或网络数据未确认时保持缺失，不以模拟值替代。系统只生成辅助决策与人工复核记录，绝不自动提交申报、交易或模型晋级。
